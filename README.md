# 顾手游电竞 · 游戏代练业务网站（静态站点）

一套可直接用浏览器打开预览的游戏代练业务站静态站点，包含**产业介绍首页**、**服务项目页**、**联系入口页**、**管理后台**四个页面。

## 一、目录结构

```
output/
├── index.html            首页（游戏代练产业介绍 + 平台数据 + 核心优势 + 下单流程）
├── services.html         服务项目页（六大服务 + 分游戏价目表 + 服务保障 + FAQ）
├── contact.html          联系入口页（联系方式 + 在线需求表单 + 其他沟通渠道）
├── admin-<随机>.html    管理后台（隐藏入口：文件名不可猜测，无前台链接，需在地址栏输入完整文件名访问）
├── README.md             本说明文件
└── assets/
    ├── css/
    │   └── style.css     全站统一样式（深色电竞风、响应式）
    ├── data/
    │   └── site-data.json 线上已发布的内容数据（由后台「发布到线上」提交到仓库，首次发布时自动创建）
    └── js/
        ├── site-data.js    前台内容数据源（默认内容 + 线上已发布数据 + 读写 localStorage + 渲染前台页面）
        ├── main.js         前台公共脚本（导航、标签页、FAQ 折叠、复制、返回顶部、Toast）
        ├── order-form.js   联系页需求表单校验 + 本机存储
        ├── admin-auth-config.js 管理后台管理员账号配置（登录账号 / 密码 / 顶栏显示名，由站长本人修改）
        ├── admin.js        后台基础交互逻辑（登录、看板、订单、服务、留言、设置）
        ├── admin-content.js 后台「内容管理」编辑器（可视化修改前台内容并保存）
        └── admin-publish.js 后台「发布到线上」（通过 GitHub API 提交数据文件、触发 Pages 重建）
```

## 二、如何使用

1. 直接双击 `index.html`，用浏览器（Chrome / Edge）打开即可预览，无需服务器、无需联网。
2. 顶部导航可在四个页面之间跳转。
3. 进入 **管理后台** 需登录：管理员账号与密码**由你自己设置**，位置是 `assets/js/admin-auth-config.js`（详见第八节「管理后台管理员账号配置」）。**首次使用前必须先填写该文件**，否则后台无法登录，页面会提示「管理员账号尚未配置」。
4. 想改站内文案、价格、联系方式，登录后台后进入 **内容管理** 页面修改（详见下一节）。
5. 改完想让**公网访客**也看到，需要把内容**发布到线上**（详见第四节）：在后台 **🚀 发布到线上** 填一次 GitHub Token，之后每次改完点「立即发布到线上」即可，约 1 分钟后全站生效。线上网址：`https://gushouyou.top/`。

## 品牌名称与 Logo（全站统一）

- **品牌名称**：顾手游电竞；副标英文小字 `GU ESPORTS`（显示在页头 / 页脚 logo 名称下方）。
- **Logo 图形**：页头、页脚、后台顶栏、后台登录门的圆角渐变徽标内统一使用品牌字 **「顾」**（`<span class="logo-mark">顾</span>`）。如需换回图形图标，把徽标内的内容换回 `<svg>…</svg>` 即可，样式见 `assets/css/style.css` 里的 `.logo-mark` 与 `.logo-mark svg`。
- **文案来源**：站点名称、副标题、标语、页脚简介 / 版权 / 联系方式等全部来自数据层的 `brand` 与 `footer` 分组（默认值在 `assets/js/site-data.js` 的 `DEFAULTS` 中），也可登录后台在 **内容管理 → 品牌信息与页脚** 里直接修改。
- **页面标题与描述**：`<title>`、`<meta name="description">` 写在 `index.html`、`services.html`、`contact.html`、`admin.html` 的 `<head>` 中，改品牌名时这几处需一并修改（本次更名已同步）。
- **旧数据自动更名**：如果本机浏览器里已经存过旧品牌的内容（`localStorage` 键名 `gb_site_v1`），前台/后台打开时会自动把旧字串（`GameBoost`、`GameBoost 极速代练`、`GameBoost_CS`、`service@gameboost.demo`、`WHY GAMEBOOST` 等）替换为新品牌并回写本机数据，无需手动清除浏览器缓存。

## 三、如何修改网站内容（含生效方式）

站点采用「**一份数据、前后台共用**」的结构：前台页面不再写死文案，而是打开时读取一份内容数据并渲染。后台「内容管理」就是这份数据的可视化编辑器。

### 1. 操作路径

1. 用浏览器打开后台入口页（站点根目录下 `admin-` 开头的隐藏文件，文件名不可猜测；在浏览器地址栏输入完整文件名即可访问），输入你在 `assets/js/admin-auth-config.js` 中设置的管理员账号与密码登录；
2. 左侧进入 **📝 内容管理**（默认首页），页面按分组折叠展示，共 13 组：
   - 品牌信息与页脚（站点名称、副标题、标语、页脚简介 / 版权 / 提示语 / 页脚导航与联系方式列表）
   - 首页 · 首屏大图区（标题、简介、按钮文字、右侧进度看板条目）
   - 首页 · 产业介绍（小标题、大标题、说明、六张产业卡片）
   - 首页 · 平台数据（8 项指标）
   - 首页 · 核心优势
   - 首页 · 服务流程
   - 首页与服务页 · 行动号召条
   - 服务页 · 页头与区块文案
   - 服务项目与价格（含「是否上架」开关，关掉前台即不显示该服务）
   - 服务页 · 分游戏价目表（游戏 / 服务项目 / 段位区间 / 参考单价 / 预计工时 / 状态标签）
   - 服务页 · 保障条款与常见问题
   - 联系页 · 页头与表单文案
   - 联系方式与咨询渠道（客服 QQ / 微信 / 邮箱 / 热线 / 服务时间、**客服二维码图片**、二维码卡片标题与说明、其他沟通渠道卡片）
3. 直接改输入框 / 下拉框 / 开关，选择项可增删（「+ 新增一项」/「删除此项」，删除时会二次确认）；
4. 点右上角 **保存并生效**（也可按 `Ctrl + S`），看到提示「内容已保存，前台页面刷新后立即生效」即完成。

### 2. 修改后如何生效

- **保存 → 前台刷新（F5）** 即可看到新内容，无需重启、无需重新生成文件。
- ⚠️ 注意：这一步**只写进本机浏览器**，你自己能看到，**公网访客还看不到**。要让所有访客都看到，请到 **🚀 发布到线上** 点「立即发布到线上」（详见第四节）。
- 页面右上角提供「前台预览入口」（首页 / 服务与价目 / 联系下单），可一键在新标签页核对效果。
- 未保存时页面顶部会提示「● 有未保存的修改」，此时关闭或刷新后台会弹出离开确认，避免误丢改动。

### 3. 三个补充按钮

| 按钮 | 作用 |
| --- | --- |
| 保存并生效 | 把当前修改写入本机数据，前台刷新即生效 |
| 导出内容 JSON | 把当前全部内容导出为 `gushou-site-content.json`，用于备份 |
| 恢复默认内容 | 清除本机自定义内容，前台回到初始示例文案（不可撤销，会二次确认） |

### 4. 客服二维码图片怎么设置（联系页）

联系页底部的客服二维码卡片支持上传真实二维码，操作路径：**📝 内容管理 → 联系方式与咨询渠道 → 客服二维码图片（上传本地图片 / 填图片地址）**。

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 上传本地图片 | 点字段右侧 **上传本地图片**，选择电脑上的二维码图片（jpg / png / webp） | 图片会被转成 **base64** 存进站点数据，不需要额外上传文件，随「发布到线上」一起提交，访客也能看到 |
| 填写图片地址 | 在输入框里直接填路径或网址，如 `assets/img/qr.png`、`https://…/qr.png` | 适合图片已经放进仓库或托管在图床上的情况；输入框失焦后左侧会显示预览 |
| 清除图片 | 点 **清除图片** | 清空后联系页恢复显示文字占位（即上面的「未设置二维码图片时的文字占位」，通常不用改） |

注意事项：

- **图片体积**：单张上限 500 KB，建议先压缩到 **300 KB 以内**（微信 / 支付宝导出的二维码通常只有几十 KB）。二维码图片会变成文本存在数据文件里，图片越大发布越慢、也越容易失败；超过上限时后台会拒绝并给出提示。
- 格式建议用 **png**（清晰、体积小、支持透明）；如果二维码来自聊天工具截图，先裁剪掉多余留白再上传，扫码识别更稳。
- 上传或清除后**务必点右上角「保存并生效」**，前台刷新（F5）即可看到效果。这一步只写本机，要让公网访客也看到，还需到 **🚀 发布到线上** 点「立即发布到线上」（二维码图片会跟着内容一起提交）。
- 二维码卡片上方的标题与说明（「扫码添加专属客服」等）是另外两个字段，可按需一起修改。

### 5. 注意事项

- 内容保存在**本机浏览器**（`localStorage`，键名 `gb_site_v1`），**换电脑、换浏览器或清理浏览器数据后会回到默认内容**；重要内容请先「导出内容 JSON」备份。
- 后台「服务管理」改起步价 / 上下架、「站点设置」改站点名称与客服信息，同样会**自动同步**到内容管理这份数据（打开内容管理时若检测到差异会提示「已同步…」），两处改任一处前台都会生效；但同一字段以**最近一次保存**为准。
- 「是否上架」开关：关闭后该服务不会出现在前台服务页，同时也从联系页表单的「服务类型」下拉中移除。
- 少数标题字段（如首页主标题、区块标题）标注了「支持 HTML」，可在文案中直接写 `<span class="grad">关键词</span>`、`<br>` 等标签做高亮或换行；其余字段按纯文本渲染，不要写标签。
- 标注「每行一条 / 每行一项」的多行输入框（如服务要点、页脚列表）：一行对应前台的一个条目，空行会被忽略。
- 价目表的「状态」与「状态色调」要配套设置：色调决定前台标签颜色（绿 / 橙 / 黄 / 蓝 / 灰）。

## 四、发布到线上（让公网访客看到你的修改）

> 「内容管理 → 保存并生效」只把内容写进**本机浏览器**，访客看不到。本节介绍如何把内容**发布到线上**：通过 GitHub API 把数据文件提交到仓库，触发 GitHub Pages 自动重建，约 1 分钟后**所有访客**打开公网网址看到的都是最新内容。全程零成本、不需要服务器。

发布链路：**本机后台改内容 → 保存并生效 → 点「立即发布到线上」→ 提交到 GitHub 仓库 → Pages 自动重建（约 1 分钟）→ 公网访客看到新内容**

### 1. 一次性准备

#### 1.1 确认仓库与 Pages 已就绪

| 项目 | 值 |
| --- | --- |
| 仓库 | `gushouyou/gushou-esports` |
| 分支 | `main`（以后台实际读取到的仓库默认分支为准） |
| 数据文件 | `assets/data/site-data.json`（首次发布时自动创建） |
| 公网网址 | `https://gushouyou.top/` |

进入仓库 **Settings → Pages**，Source 选 `Deploy from a branch`，Branch 选 `main`、目录选 `/ (root)` 后保存；等待 1~2 分钟即可用上面的网址访问。若仓库里还没有 `assets/data/site-data.json`，访客会先看到内置默认内容，首次发布后即变为你发布的内容。

#### 1.2 生成 GitHub 细粒度 Token（分步指引）

1. 浏览器登录 GitHub → 右上角头像 → **Settings**；
2. 左侧栏最下方 → **Developer settings**；
3. 展开 **Personal access tokens** → 点 **Fine-grained tokens**；
4. 点右上角 **Generate new token**，如需要先完成邮箱验证等提示操作；
5. 填写基本信息：
   - **Token name**：`gushou-site-publish`（随意取名，便于以后识别）
   - **Expiration**：建议 90 天（到期后重新生成一个替换即可；也可选更长有效期）
   - **Resource owner**：选择你自己的账号 `gushouyou`
6. **Repository access** 选 **Only select repositories**，在下拉框中**只勾选** `gushou-esports`（不要选 All repositories）；
7. 展开 **Repository permissions**，只修改一项：**Contents** → 选择 **Read and write**（其余项保持默认的 No access，最小授权）；
8. 页面底部点 **Generate token**，顶部会显示一串以 `github_pat_` 开头的字符 —— **它只显示这一次**，请立即复制；
9. 回到后台：打开后台入口页 → 左侧 **🚀 发布到线上** → 把 Token 粘贴进输入框 → 点 **保存 Token**，出现「Token 已保存到本机浏览器」即成功（输入框旁的徽标会从「未填写」变为「已保存到本机」）。

> 🔐 **安全提示（务必阅读）**
> - Token 相当于这个仓库的**写入钥匙**，只保存在**本机浏览器**（`localStorage`，键名 `gb_gh_token`），不会上传任何服务器，也不会随网站文件发布出去；
> - 请勿在公共电脑 / 他人电脑上保存；请勿粘贴到聊天、工单、截图或代码仓库里；
> - 一旦怀疑泄露，立即到上一步的页面 **Revoke**（吊销）该 Token 并重新生成一个；
> - 本机用完可在后台点 **清除 Token**，把它从浏览器里彻底删除（线上网站与已发布内容不受影响）；
> - 线上后台页面本身是公开可访问的，但**没有 Token 的访客只能改自己浏览器里的内容，无法改动线上内容**，因此请妥善保管 Token，不要在后台留下敏感信息。

### 2. 日常发布流程（3 步）

1. **改内容**：后台 **📝 内容管理** 改好文案 / 价格 / 联系方式，点 **保存并生效**；
2. **发布**：切到 **🚀 发布到线上**，点右上角 **立即发布到线上**，确认弹窗中显示的仓库、分支、数据文件、内容大小无误后点「确定」；
3. **等约 1 分钟**：页面步骤面板依次给出结果——① 校验 Token 与仓库权限 → ② 读取线上数据文件版本 → ③ 提交数据文件 → ④ 等待 GitHub Pages 重建。完成后打开公网网址核对，必要时按 `Ctrl + F5` 强刷，或在网址后加 `?v=2` 绕过浏览器缓存。

要点：

- 发布提交的是**「内容管理」中已保存的内容**。若后台顶部仍提示「● 有未保存的修改」，请先保存再发布（发布前的检查清单也会提示「内容管理：有未保存的修改」）。
- **检测线上连接** 按钮：随时检查 Token 权限、线上数据文件版本，并对比「本机内容」与「线上内容」是否一致；点发布时会自动再做一次校验。
- 每次发布会生成一条提交记录，提交信息为「更新站点内容（后台发布 YYYY-MM-DD HH:MM:SS）」，可在页面底部点「查看提交记录」追溯。
- 发布记录（时间 + commit 号）存在本机浏览器（键名 `gb_publish_meta`），仅用于在后台显示「上次发布」信息。
- 发布提交的是**整份内容数据**，**后台上传的客服二维码图片（base64）也包含在内**，因此二维码无需单独上传到仓库即可让访客看到。图片越大数据文件越大（发布弹窗会显示「内容大小」），建议把二维码压缩到 300 KB 以内再上传。
- 建议直接在**线上后台** `https://gushouyou.top/admin.html` 操作发布：Token 与内容数据都按浏览器站点归属保存，本机用 `file://` 打开的后台与线上后台的数据互不相通，两边需要分别粘贴一次 Token。

### 3. 为什么发布后所有人就都能看到

前台页面打开时会读取仓库里的数据文件 `assets/data/site-data.json`（由 `assets/js/site-data.js` 的 `loadRemote()` 负责，请求带 `?v=时间戳` 以避开 CDN 缓存）。**数据优先级：本机浏览器数据 > 线上已发布数据 > 内置默认数据**：

- 访客的浏览器里没有本机数据，因此看到的就是**线上已发布数据**；
- 站长本机有自己的 `localStorage` 数据，改完保存会先在本机看到效果，发布后线上数据同步更新，访客随之看到；
- 若本机清除了浏览器数据，本机打开的页面也会退回显示线上已发布数据。

### 4. 发布状态反馈与常见失败排查

页面 **② 发布目标与检查** 区会实时显示三项状态：Token 是否已保存、内容管理是否有未保存修改、线上数据与本机是否一致；点发布后，**步骤面板** 会逐步显示每一环节的结果与失败原因（英文报错已转为中文可操作说明）。

| 现象 | 原因与处理 |
| --- | --- |
| Token 无效（401） | Token 没粘贴完整、已过期或被吊销。重新生成一个细粒度 Token 后重新保存。 |
| 没有写入权限（403） | Token 的 **Contents** 不是 **Read and write**，或没有勾选本仓库；权限修改后必须**重新生成** Token（旧 Token 权限不会自动更新）。也可能是提交过于频繁触发限流，等几分钟再试。 |
| 找不到仓库 / 文件（404） | 仓库名、分支写错，或 Token 未授权该仓库。线上还没有数据文件属正常现象，首次发布会自动创建。 |
| 版本冲突（409） | 线上文件刚被别的改动更新过。点 **检测线上连接** 刷新版本后重新发布。 |
| 网络请求失败 | 本机连不上 `github.com`（网络 / 代理 / 防火墙），或本页是用 `file://` 双击打开的。请确认浏览器能正常访问 GitHub，并改用线上网址打开后台。 |
| 发布成功但访客看到的还是旧内容 | ① Pages 还在重建，等 1 分钟再刷新；② 浏览器缓存，按 `Ctrl + F5` 强刷或加 `?v=2`；③ 到仓库 **Settings → Pages** 确认 Pages 已启用。 |
| 只在本机看得到改动 | 还没发布或发布失败。「保存并生效」只写本机浏览器，必须点 **立即发布到线上**。 |

## 八、管理后台管理员账号配置（含生效方式与安全边界）

后台登录门的管理员账号与密码**不再写死在页面代码里**，已抽取到独立配置文件 `assets/js/admin-auth-config.js`，由站长本人自行修改。

### 1. 修改位置

打开 `assets/js/admin-auth-config.js`（记事本 / VS Code 均可），修改下面三个字段后保存：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `username` | 必填 | 你的管理员登录账号，建议不要用 `admin`、`root`、`123456` 这类易猜词 |
| `password` | 必填 | 你的管理员登录密码，建议 12 位以上、字母数字符号混合 |
| `displayName` | 可选 | 登录后后台顶栏显示的名字，留空则显示「管理员」 |

示例：

```js
window.GB_ADMIN_AUTH = {
  username: "gushou_admin_2026",
  password: "换成一个只有你自己知道的密码",
  displayName: "站长"
};
```

### 2. 生效方式

- 保存文件后，回到后台页面按 **Ctrl + F5**（强制刷新，避免浏览器继续用旧缓存）即生效，无需重启服务、无需重新发布内容。
- 如果当时已经进了后台，请先点右上角 **退出登录**，再刷新让登录门重新出现。
- 改过账号或密码后，旧的登录状态会立即失效（登录标记里存的是账号名，对不上就要求重新登录）。
- 线上（GitHub Pages）同理：把改好的 `assets/js/admin-auth-config.js` 一起提交到仓库，访客打开的后台才会用新账号；否则线上仍是旧配置。
- 未填写 `username` / `password` 时，后台会显示「管理员账号尚未配置：请打开 assets/js/admin-auth-config.js…」并且无法进入，属正常现象，填完刷新即可。

### 3. 安全边界（务必了解）

本站是**纯静态站点**（只有 HTML / CSS / JS，没有服务端、没有数据库鉴权），后台登录只是一次**前端字符串比对**：

- **账号密码是明文**：任何人打开 `assets/js/admin-auth-config.js` 或查看页面源码，都能直接看到你填的账号与密码，它无法被加密。
- **可被绕过**：有技术基础的人无需密码也可绕过这道门（例如在浏览器控制台手动写入登录标记，或直接查看后台所读的本机数据）。因此它**不是**真正的访问控制。
- **它实际能挡住什么**：防止访客随手点进后台、避免后台被误当成公开页面，即一层「防误入」的门槛。
- **什么时候必须换成真鉴权**：只要后台要管理真实订单、真实用户资料，或站点正式对外运营，就必须改用服务端鉴权（例如由服务端校验管理员身份），否则任何人都能打开后台页面。
- **不要把真实敏感信息交给后台**：当前后台的内容（价格文案、示例订单、联系方式、GitHub Token 仅存本机）都属于「可公开的站点内容 + 本机数据」，不适合存放真实客户隐私或支付信息。
- **提交到公开仓库就等于公开**：一旦把整套文件推送到公开仓库（含 GitHub Pages 发布），配置文件也会一并公开；要保密只能不把后台部署到公网，或改用服务端鉴权。

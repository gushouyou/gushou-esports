发布到线上

把「内容管理」里保存好的内容提交到 GitHub 仓库，GitHub Pages 会自动重建（约 1 分钟），此后所有访客打开公网网址看到的都是最新内容。

发布是怎么生效的

零成本方案 · 无需服务器
本机后台改内容 → 保存并生效 → 点「立即发布到线上」 → 提交到 GitHub 仓库 → Pages 自动重建（约 1 分钟） → 公网访客看到新内容

访客打开网站时，页面会读取仓库里的数据文件 assets/data/site-data.json；本站的文案、价目表、联系方式等全部存在这个文件里，所以只要它更新，全站内容就更新了——不用改代码，也不用买服务器。

① GitHub Token（只需填一次）

未填写

Token 是你在 GitHub 生成的「写入钥匙」，用来授权本后台提交这一个仓库的文件。它只保存在本机浏览器（localStorage 键名 gb_gh_token），不会上传到任何服务器，也不会随网站文件发布出去。生成时请只勾选仓库 gushouyou/gushou-esports，权限只给 Contents: Read and write（分步指引见站点 README 的「发布到线上」一节）。

安全提示：Token 一旦泄露，他人就能改动你的线上内容（篡改或删除数据文件）。请不要在公共电脑、他人电脑上保存；不要把它粘贴到聊天、工单或截图里；一旦怀疑泄露，立即到 GitHub 的 Settings → Developer settings → Personal access tokens 里 Revoke（吊销）它并重新生成。用完本机后可点上方「清除 Token」，把它从浏览器里彻底删除。

③ 发布失败怎么排查？（点开查看）
现象原因与处理
提示 Token 无效（401）Token 没粘完整、已过期或被吊销。重新生成一个细粒度 Token（仓库选 gushou-esports、权限勾 Contents: Read and write），再「保存 Token」。
提示没有写入权限（403）Token 的「Repository permissions → Contents」不是 Read and write，或没勾选本仓库。改权限后必须重新生成 Token（旧 Token 的权限不会自动更新）。
找不到仓库 / 文件（404）仓库名、分支写错，或 Token 未授权访问该仓库。本页顶部的仓库 / 分支 / 文件路径要和 GitHub 上完全一致。线上还没有数据文件属正常，首次发布会自动创建。
版本冲突（409）线上文件刚被别的改动更新过。点「检测线上连接」刷新版本，再发布一次即可。
网络请求失败本机连不上 github.com（网络 / 代理 / 防火墙），或本页是用 file:// 双击打开的。先确认浏览器能正常访问 github.com，再改用线上网址打开后台。
发布成功但访客看到的还是旧内容① GitHub Pages 还在重建，等 1 分钟再刷新；② 浏览器缓存，按 Ctrl+F5 强刷，或在网址后加 ?v=2；③ 到仓库 Settings → Pages 确认 Pages 已启用。
只在本机看得到改动说明还没发布或发布失败。「保存并生效」只写本机浏览器；要让访客看到，必须在本页点「立即发布到线上」。
